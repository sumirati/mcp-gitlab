# Release Management Runbook (`release-mgmt.md`)

This runbook documents the standard release process for `@sumirati/mcp-gitlab` across all supported platforms:
- **Git Repositories**: Self-hosted GitLab, [GitHub](https://github.com/sumirati/mcp-gitlab), and [GitLab.com](https://gitlab.com/sumirati/mcp-gitlab)
- **Package Registry**: [npm (`@sumirati/mcp-gitlab`)](https://www.npmjs.com/package/@sumirati/mcp-gitlab)
- **MCP Catalog**: [Model Context Protocol Registry (`io.github.sumirati/mcp-gitlab`)](https://registry.modelcontextprotocol.io/)

---

## Prerequisites

- Node.js >= 18.0.0 & npm installed
- `mcp-publisher` CLI tool installed at `~/bin/mcp-publisher`
- Git working directory clean (`git status`)

---

## Release Checklist & Execution Steps

### Step 1: Bump Version Numbers

Ensure semantic versioning (e.g. bumping `1.0.1` $\rightarrow$ `1.0.2` or `1.1.0`). Update the version in the following 4 files:

1. **`package.json`**:
   ```json
   "version": "X.Y.Z"
   ```
2. **`package-lock.json`**:
   Update both root and package entry:
   ```json
   "version": "X.Y.Z"
   ```
3. **`server.json`** (MCP Registry manifest):
   Update both root `version` and the `packages[0].version`:
   ```json
   "version": "X.Y.Z",
   "packages": [
     {
       "identifier": "@sumirati/mcp-gitlab",
       "version": "X.Y.Z"
     }
   ]
   ```
4. **`index.js`** (Server constructor):
   ```javascript
   const server = new Server(
     {
       name: "@sumirati/mcp-gitlab",
       version: "X.Y.Z",
     },
     ...
   );
   ```

---

### Step 2: Git Commit & Tag

Stage the updated files, create the release commit, and tag the release:

```bash
git add package.json package-lock.json server.json index.js
git commit -m "chore: bump version to X.Y.Z"
git tag -a vX.Y.Z -m "Release vX.Y.Z"
```

---

### Step 3: Push to Git Remotes

Push both the branch and the release tag to your primary GitLab remote:

```bash
git push origin main
git push origin vX.Y.Z
```

> [!NOTE]
> Pushing to `origin` automatically syncs the release commit and tag to your push mirrors on **GitHub** (`github.com/sumirati/mcp-gitlab`) and **GitLab.com** (`gitlab.com/sumirati/mcp-gitlab`).

---

### Step 4: Publish to npm

Publish the new version publicly to npm:

```bash
npm publish --access public
```

> [!TIP]
> `npm publish` handles authentication automatically — if your session is expired or not authenticated, npm will initiate the browser login prompt inline.

Verify the release on npm:
- [https://www.npmjs.com/package/@sumirati/mcp-gitlab](https://www.npmjs.com/package/@sumirati/mcp-gitlab)

---

### Step 5: Publish to Model Context Protocol Registry

The MCP Registry indexes server metadata and requires active GitHub authentication to verify ownership of the `io.github.sumirati` namespace.

> [!WARNING]
> **JWT Token Lifetime < 10 Minutes:**  
> The authentication JWT generated by `mcp-publisher` has a short expiration window (under 10 minutes). Always execute the `login` command immediately prior to `publish`.

```bash
# 1. Authenticate with GitHub (complete device code / browser prompt)
~/bin/mcp-publisher login github

# 2. Publish updated metadata to the registry
~/bin/mcp-publisher publish
```

---

### Step 6: Verification

Verify the release across distribution channels:

1. **npm**:
   ```bash
   npm view @sumirati/mcp-gitlab version
   ```
2. **MCP Registry**:
   Check listing on [registry.modelcontextprotocol.io](https://registry.modelcontextprotocol.io/) under `io.github.sumirati/mcp-gitlab`.
3. **Live Test**:
   ```bash
   npx -y @sumirati/mcp-gitlab@latest
   ```
